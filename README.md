# 批量解压工具（Archive Unpacker）

一个面向 Windows 的桌面批量解压工具。为「一堆来历不明的压缩包 + 层层套壳 + 各种伪装后缀 + 若干候选密码」这类脏活设计：
丢进去一批文件，剩下的交给它，解到头、把成果搬到你指定的目录。

界面是纯中文，基于 Electron + TypeScript，判定逻辑全部跑在主进程。

## 它解决什么问题

实际遇到的压缩包往往长这样：

- 后缀是 `.png` / `.mp4` / `.pdf`，其实是压缩包（为了绕过网盘审查）；
- 解出来里面还套着包，一层、两层、三层；
- 包是加密的，密码得从一堆候选里试；
- 是 `.lz4` 压缩流，7-Zip 根本不认；
- 是分卷（`.7z.001` / `.part1.rar`），还得先合起来；
- 文件名没后缀，或者前面被硬拼接了几百 MB 视频数据。

这个工具的目标就是：**把这些包丢进一个文件夹，点一次开始，最后得到解好的成品。**

## 功能一览

| 能力 | 说明 |
| --- | --- |
| 批量解压 | 一次处理整个文件夹，并发 3 个 |
| 多候选密码 | 自动逐个尝试；支持「按文件名前缀绑定密码」 |
| 伪装后缀 | 把 `.png/.mp4/.jpg` 这类实为压缩包的文件认出来 |
| 嵌套解压 | 解出来的包里还有包，自动继续往下解 |
| 自动搬运 | 判定「解到头」后，把成品文件夹搬回压缩包所在目录，并清掉一路留下的空壳 |
| 无后缀包 | 按文件头识别，解压前自动补 `.zip` |
| 前置数据剥离 | 剥离「视频 + 尾部 zip」这类文件开头的无关数据后再解 |
| LZ4 支持 | 自研解码器（7-Zip 不支持 lz4），解出内层后继续走正常流程 |
| 分卷自动合并 | `.7z.001`、`.part1.rar` 这类分卷自动识别为一个包 |
| 7-Zip 校验 | 可选：扫描和解压时用 7-Zip 实际打开文件判断，避免误判 |

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11（64 位） |
| 7-Zip | **必需**，建议 7-Zip 24+（默认路径 `C:\Program Files\7-Zip\7z.exe`） |
| Node.js | 仅「从源码运行 / 自行打包」时需要，22 或更高 |

## 快速上手

1. **选择「压缩包文件夹」** —— 你的包放在哪，就选哪个目录（输入或点「浏览」）。
2. 选好后会**自动扫描**，列出识别到的压缩包（含分卷合并、伪装后缀、无后缀文件）。
3. （可选）在下方**候选密码**里加上你常用的密码；给密码填「前缀」可以只对特定开头的包生效。
4. 点 **开始解压**。过程中可以在「运行日志」里看到每一步判定，进度条显示整体进度。

结束后：

- 成品会被搬到「压缩包文件夹」根目录（如果判定为「解到头」）；
- 中间的嵌套包如果还在队列里，会继续解完；
- 失败/密码错误的包会原样保留，不会动你的源文件。

## 核心机制：嵌套解压与自动搬运

这是整个工具最需要理解的规则。解压完一层之后，程序会按**固定顺序**做判断：

### 判定顺序

1. **成品检测 · 套壳形态**
   输出目录里**恰好只有一个文件夹**，且该文件夹里有**多于 1 项** → 判定为「解到头」。
   → 把这个文件夹搬回「压缩包文件夹」根目录，并清掉一路留下的空壳目录。
   （最外层也适用：顶层包解出唯一一个游戏目录，也会直接搬上来。）

2. **成品检测 · 散装形态**
   输出目录**顶层直接有多个文件/文件夹**（大于 1 项）→ 判定为成品，整个输出目录就是成果。
   注意：**成品判定优先于阈值**——哪怕解出 30 个文件，只要形态符合就先当成品。
   最外层不做这一步（输出目录本来就在源目录里，搬了等于没搬）。

3. **单文件套壳**
   上一层只解出 **1 个文件**，且它的后缀是你登记过的「伪装后缀」→ 直接改名后继续解（不额外调用 7-Zip 探测）。

4. **阈值收手**
   上一层解出的文件数**超过「嵌套解压阈值」**（默认 3）→ 认为已经解到正常内容，停止。
   这是最常触发的一条：一次解出一两千个文件，就说明到头了。

5. **严格扫描**
   以上都不满足时，用 7-Zip 逐个试探输出目录顶层的文件：**只有真能列出清单的**才继续解。
   → 这一条挡住解出来的真图片/真视频；同时让「套着 .jpg 壳的真压缩包」照样被识别。

### 自动搬运

触发「成品」后，程序会：

1. 把成品文件夹移到「压缩包文件夹」根目录；
2. 目标重名时自动加 ` (1)`、` (2)`，**绝不覆盖**；
3. 向上清理**确认是空**的外壳目录（非递归删除，任何一个不为空就保留并提示）；
4. 如果成品名和外壳名撞车（例如整条链都叫 `A41`），会先落到 `A41(1)`，等外壳清干净后**再改回 `A41`**。

## 设置项详解

打开右上角「设置」：

### 解压选项

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 包含子文件夹 | 开 | 递归扫描「压缩包文件夹」下的所有子目录 |
| 每个包独立文件夹 | 开 | 每个包解到以自己名字命名的子目录，避免不同包的几百个文件混在一起 |
| 嵌套解压阈值 | 3 | 一层解出超过这么多个文件就不再往下解（见上文判定第 5 条） |
| 伪装后缀自动改名后解压 | 开 | 把 `.png` 这类伪装文件永久改名为 `.zip` 再解压（只改名，不动内容） |
| 改名后缀 | zip | 改名时用的后缀。7-Zip 按文件头识别真实格式，写 zip / rar / 7z 都行 |
| 解压成功后删除源压缩包 | 开 | **只在成功时删除**；失败或密码错误一律保留。分卷一并删除 |
| 解压前用 7-Zip 校验 | 建议开 | 扫描阶段实际打开文件确认是不是压缩包，比只看后缀准；文件多时稍慢 |
| 7-Zip 路径 | 自动检测 | 没检测到时手动选 `7z.exe` |

### 伪装后缀

你登记的后缀列表。含义：**这些后缀的文件可能是压缩包**。

典型值：`png`、`mp4`、`jpg`、`pdf`、`tif`、`xls`、`gif`、`json`、`dll`……

- 关闭「7-Zip 校验」时：列表里的文件一律直接当压缩包列出（快，但可能混进真图片）；
- 开启「7-Zip 校验」时：由 7-Zip 实际判定，真图片会被排除，套壳的包被认出来。

> 提示：如果只是想「看见就解」，把后缀登记上、关掉校验最省事；
> 如果目录里混了大量真媒体文件，建议开启校验。

## 个人配置（personal-settings.json）

程序支持一个可选的配置文件，用于「换机器 / 重装后一键恢复成自己熟悉的样子」。

- 模板见 [`personal-settings.example.json`](./personal-settings.example.json)，复制为 `personal-settings.json` 后填入自己的值。
- **生效时机**：仅当本机还没有设置记录（首次运行）时导入；之后你在界面里的改动以本机为准，不会被文件覆盖。
- 可配置：全部设置项、候选密码、伪装后缀列表。
- 该文件默认已被 `.gitignore` 忽略，**不会误传到公开仓库**。

> ⚠️ 如果配置里包含真实密码，务必只放在**私有仓库**或本机，不要提交到公开仓库。

## 打包成 exe

项目已配置 [electron-builder](https://www.electron.build/)：

```bash
# 产出免安装的目录版：release/win-unpacked/
npx electron-builder --win dir --x64
```

双击 `release/win-unpacked/` 里的 exe 即可运行，**不需要 Node.js**。
在桌面创建快捷方式指向它，用起来就和普通软件一样。

> 建议用**目录版**（秒开）。如果打成单文件便携版（`--win portable`），第一次启动时要先把约 240MB 内容解压到系统临时目录，会明显卡一下且没有任何界面提示，容易误以为「双击没反应」。

### 图标

图标在 `build/icon.ico`（9 档尺寸，含 16/32/48/256）。
要换图标：替换 `scripts/generate-icon.py` 里的源图路径后运行它，或在 `package.json` 的 `build.win.icon` 指向新的 `.ico`。

## 常见问题

**Q：扫描不到我的压缩包？**
A：先确认后缀在识别范围内（zip/rar/7z/tar/gz… 或无后缀）；伪装后缀的文件需要你先在设置里登记该后缀。
如果开了「7-Zip 校验」仍扫不到，多半是文件本身损坏，或前置数据过多——后者可能被自动剥离后解压成功。

**Q：解压失败，提示找不到输出目录 / 无法创建目录？**
A：源文件没有后缀时，输出目录会和源文件同名。程序会在解压前自动给源文件补 `.zip` 规避，如果仍遇到，把源文件手动改名加后缀即可。

**Q：为什么解出两三个文件就不往下解了？**
A：被「嵌套解压阈值」拦住了，或已判定为成品。具体原因看日志——每一步都会写明。

**Q：为什么有的包解完没有自动搬运？**
A：搬运只在判定为「成品」时发生，且最外层不做「散装成品」判定（避免把源目录本身搬走）。
另外，如果这个包是程序「挖」出来的嵌套包，中途重启程序后它会被当成普通顶层包，层级信息丢失就不会触发搬运。

**Q：`.lz4` 文件怎么处理？**
A：程序自己解（内置 LZ4 Frame 解码器），解出内层后若是压缩包会继续走正常流程，若不是则直接落盘。

**Q：会覆盖我的文件吗？**
A：**不会**。搬移重名时自动加序号；删目录只用非递归删除且必须是空的；清理空壳时不会越过「压缩包文件夹」本身；解压失败一律保留源文件。

**Q：程序会联网吗？**
A：不会。全程本地运行，不上传任何数据。
